# Проверка текстовой сборки — 22.09.2026

Продолжение [клиентского аудита](2026-09-22-client-photo-audit.md) и [исправлений фото](2026-09-22-photo-fixes.md). Это отдельные изменения внутри уже существующего рабочего диффа.

## Подтверждённые ошибки

- Существующее значение характеристики могло пройти финальную сборку без ссылки и выдержки, хотя новые поля требовали доказательств.
- Пометка `corrected` принималась даже при неизменившемся значении. В клиентском случае агент писал, что Wi-Fi 6E не подтверждён, но оставлял Wi-Fi 6E в карточке.
- Известный URL сам по себе позволял принять новую цитату, не сверяя её с сохранёнными данными.
- Замена ранее процитированных 64 ГБ на 48 ГБ не требовала явно рассмотреть старый и новый источники.
- Отключение новых проверок обходило запрет публикации неподтверждённой карточки. Изменение перевода не снимало старую отметку согласования.

## Что исправлено

1. `ProductSpecificationEvidenceGuard` проверяет каждое сохраняемое поле: ссылка и выдержка должны присутствовать; выдержка сопоставляется с уже сохранённым текстом или цитатами исследования именно этого URL. Пробелы, HTML-сущности и зарегистрированные конечные адреса редиректов учитываются.
2. `corrected` с прежним значением и `confirmed` с изменённым значением возвращаются агенту как конкретные ошибки. Исправление требует объяснения.
3. При расхождении процитированных значений или удалении ранее поддержанного поля ответ должен перечислить рассмотренные источники и объяснить применимость. Ни магазин, ни производитель, ни источник фотографий не назначаются автоматически правыми. Эквивалентность записей и принадлежность комплектации решает агент, не словарь чисел/моделей.
4. Результаты инструментов перечитываются после ответа агента: сведения, найденные в этом же вызове, доступны проверке сразу. Несколько полей могут ссылаться на один источник. Повторное скачивание уже достаточных цитат не требуется.
5. При ошибке сборщик использует существующее ограниченное восстановление с точной причиной. Общий бюджет и число попыток не увеличены; нового обязательного вызова ИИ на каждый успех нет. Граница применения — результат `reconciled`; незавершённый ответ не обязан доказывать данные, которые не будут опубликованы.
6. Выключенные проверки не превращают неподтверждённую карточку в готовую. Уже подтверждённая карточка остаётся готовой. Изменение переводов вне атомарной записи согласования снимает старую отметку.

## Проверки

- Четыре новых регрессии сначала воспроизведены на старом поведении: отсутствие цитаты, фиктивное исправление, выдуманная выдержка по известному URL, замена конфликтующего значения без разбора источников.
- Отдельно проверены сохранение старого подтверждённого факта при пустой странице фотографий, цитата с другого URL, разные написания эквивалентного значения, осмысленное удаление неприменимого поля, сохранение обоих противоречивых наблюдений.
- Интеграционный тест: агент добывает сведения во время текущего вызова, исправляет два поля с одинаковыми источниками, сборка завершается за один вызов.
- HTTP-тест Telegram: старая кнопка публикации не проводит неподтверждённую карточку даже при выключенных проверках и не запускает новый поиск.
- В тесте оформления Telegram перевод теперь входит в исходную готовую фикстуру. Прежний тест менял уже подтверждённые сведения и ошибочно ожидал сохранения готовности. Проверка снятия отметки после изменения перевода вынесена отдельно.
- Целевой набор: 64 теста, 261 проверка. Полный повторный PHP-прогон: **891 тест, 3253 проверки, 0 падений**. Первый полный прогон обнаружил описанную выше устаревшую фикстуру Telegram; после её исправления весь набор запущен заново.
- Изменения PHP отформатированы Pint; `git diff --check` чистый. JavaScript в этом раунде не менялся, Node повторно не запускался.

## Границы и оставшееся

- Это проверка происхождения и согласованности ответа, не доказательство истинности каждого предложения. Уже сохранённые цитаты первоначального исследования не перечитываются независимо. Наличие цитаты ещё не доказывает, что она действительно поддерживает всю характеристику.
- Группировка конфликтующих наблюдений использует ключ поля. Синонимы ключей, применимость источников, различие комплектаций, согласованность рекламного описания и переводов остаются задачами агента. Их качество нужно проверить на небольшом живом наборе, а не объявлять решённым числом тестов.
- Новая проверка не исправляет автоматически опубликованные клиентские товары и не переписывает старые рецепты.
- Отдельно остаются переносимость товароспецифичных старых рецептов и сохранение контекста коротких уточнений в Telegram. Приоритет чистого слайдера над маркетинговой галереей ранее отложен пользователем и здесь не включён.

Платных вызовов и живых поисков не было. Рабочая БД, фотографии, настройки, воркеры и архив клиента не изменялись. Новых кнопок проверки для пользователя не добавлено.
