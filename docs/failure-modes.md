# Что может сломаться: каталог рисков

Составлено 2026-10-21 по живым запросам (#93…#585), журналу поиска за 30 дней и аудиту кода.
Назначение — предугадывать сбои, а не чинить их по одному после жалобы. Каждая строка: что может
случиться → чем это уже закрыто → что остаётся дырой. Новый сбой в живом запросе сначала
сверяется с этим списком: если такого класса нет, класс добавляется сюда вместе с защитой.

Правила для любой новой защиты:
- Отказ одной части не роняет запрос и не превращается в молчание: оператор получает либо результат,
  либо понятное сообщение с кнопкой. Технический текст ошибки оператору не показывается.
- Защита, которая работает внутри того же процесса, что и поиск, не видит его зависания. Для
  зависаний нужен внешний наблюдатель (страж запросов).
- Неизвестность не равна отказу: timeout, пустой ответ, невалидный JSON — техническое состояние,
  а не «товара нет» или «галереи нет».
- Повтор без нового сведения не оплачивается.

`considered_source_urls` (~60 из 200 разобранных), затем пропущенный `overall_status` (18) и смена
коммерческого идентификатора без явного решения (10).
