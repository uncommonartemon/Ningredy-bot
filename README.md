# Ningredy

Каталог электроники на Laravel 13: Telegram принимает команды администратора, Laravel AI понимает запрос, ищет сначала в локальном каталоге, при необходимости исследует интернет и выполняет только разрешённые серверные операции.

## Быстрый запуск на Windows

Один раз установите зависимости и подготовьте БД:

```powershell
composer install
npm install
php artisan migrate --force
php artisan storage:link
npm run build
```

Заполните `.env`: `ADMIN_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_ALLOWED_USER_IDS` и `OPENAI_API_KEY`. Пустой `TELEGRAM_ALLOWED_USER_IDS` блокирует всех пользователей.

Для обычного запуска откройте:

```powershell
.\start-ningredy.bat
```

BAT автоматически и с перезапуском поднимает:

- Laravel на `http://127.0.0.1:8000`;
- очередь `assistant` для текстовых AI-команд;
- очередь `voice` для транскрибации;
- очередь `media` для поиска, Vision-проверки и сохранения фото;
- ngrok и синхронизацию Telegram webhook при смене URL.

Автозапуск после входа в Windows устанавливается через `install-ningredy-autostart.bat`.

Если Telegram-бот уже работает на первом компьютере, на втором запускайте **`start-without-telegram.bat`**. Он поднимает сайт, Filament и AI-помощник формы на `http://127.0.0.1:8000/admin`. Telegram webhook не меняется; ngrok, scheduler и очереди Telegram не запускаются. AI формы и безопасное удаление неиспользуемых фото обслуживаются отдельной очередью `admin-ai`. Закрытие окна останавливает только процессы этого запуска.

Этот BAT не обновляет код и не запускает миграции. Нужны установленный PHP, Node.js, зависимости Composer/npm, `.env`, применённые миграции и собранный интерфейс. База и файлы на двух компьютерах отдельные, если специально не настроено общее хранилище; Git их не переносит. На втором компьютере не запускайте обычный `start-ningredy.bat` или автоматически запускающий его обновлятор, пока бот работает на первом.

## Обновить и запустить на Windows

Для уже установленного проекта: дождитесь окончания поисков, закройте окно бота и дважды нажмите **`update-and-start.bat`**. Сначала он берёт из GitHub свежую версию самого обновления (поэтому установка любой давности обновляется по сегодняшним шагам; без интернета запускается локальная и называет причину), затем получает `origin/main`, сохраняет `.env`, согласованный снимок SQLite и `storage/app` в соседнюю папку `ningredy-backup-*`, обновляет код и зависимости по lock-файлам, применяет миграции, дополняет справочные данные (подсказки по магазинам, каталоги брендов — только недостающее, правки не трогаются), собирает интерфейс и запускает обычный launcher с проверкой компьютера. Пароли, APP_KEY и существующие товары сохраняются. Журнал: `storage/logs/update-*.log`.

Нужны Git, Composer, PHP 8.4.1+ (8.x), Node.js 22.12+ и настроенный ngrok. Обычное обновление останавливается при ошибке, работающих процессах, локальных изменениях или расхождении истории Git. Автоматический backup рассчитан на SQLite, включая свой путь `DB_DATABASE`/`DB_URL`; для другой СУБД скрипт остановится до обновления. Папка backup считается полной только при наличии `COMPLETE.txt`.

Если обновление остановилось из-за локальных изменений (например, `M package.json`) или расходящейся истории, закройте бота и запустите **`update-and-start-force.bat`**. Он сохранит базу, настройки, фото и локальный код, затем заменит код версией из GitHub и выполнит обычные установку, миграции, сборку и запуск. Локальные правки автоматически не переносятся в новую версию: они остаются в backup, в папке `local-code` (рабочие файлы, патчи индекса/рабочей копии и проверенный `repository.bundle` с коммитами). Новые локальные файлы, не пересекающиеся с кодом из GitHub, остаются на месте. Несовместимая версия PHP/Node или ошибка backup по-прежнему останавливают процесс.

На старом компьютере, где этого BAT ещё нет, откройте PowerShell **в папке проекта** и выполните:

```powershell
curl.exe --fail --location https://raw.githubusercontent.com/uncommonartemon/Ningredy-bot/main/update-and-start-force.bat --output update-and-start-force.bat
.\update-and-start-force.bat
```

Этот BAT сам получает свежие скрипты обновления во временную папку; вручную сбрасывать Git или перезаписывать старые скрипты не требуется.

Повторный запуск продолжает обычную процедуру после исправления причины ошибки. Git переносит только отправленный в репозиторий код, не каталог и фотографии с другого компьютера. `start-ningredy.bat` по-прежнему запускает без обновления. Один Telegram-бот следует запускать только на одном компьютере одновременно.

## Как работает бот

Примеры сообщений:

- `Найди у нас ноутбук с 8 GB RAM` — поиск по товарам, вариантам и характеристикам локальной БД.
- `Найди в интернете Lenovo Legion RTX 4070 серого цвета` — web research и черновик с источниками.
- `Измени цену Lenovo Legion на 900` — поиск точного товара и аудируемое изменение.
- `Скрой товар #12` — деактивация без удаления данных и фото.
- `Удалить товар #12` — только подготовка операции; физическое удаление выполняется после отдельной кнопки подтверждения.
- `Удали все черновики` — подготовка удаления всех черновиков текущего оператора в текущем чате, без перечисления ID; выполнение после кнопки подтверждения.
- `Создай группу ОЗУ и назначь её характеристикам с ID от 5 до 10` — поиск подходящей группы или создание новой и привязка диапазона одной транзакцией.
- `Найди товар по SKU ABC-123 и поменяй название на …` — поиск связанных записей и изменение нужного поля с аудитом.
- `/url` — мгновенно показать текущий ngrok URL и адрес каталога без вызова AI.
- Голосовое сообщение — качественная транскрибация, затем тот же сценарий, что для текста.
- Обычный вопрос вроде `Как дела?` — обычный ответ без вызова инструментов.

Поиск в интернете не публикует товар сразу. Бот присылает описание и кнопку добавления. После добавления отдельная media-очередь скачивает несколько кандидатов, Vision выбирает подходящие фото, сервер перекодирует их в WebP и сохраняет в `storage/app/public/products/{id}`. В Telegram отправляется уже проверенный локальный файл. WebP-перекодирование удаляет EXIF и служебные метаданные. При скрытии товара файлы остаются, при удалении товара удаляются автоматически.

Повторный запуск одной job безопасен: изменение с теми же входными данными не выполняется второй раз.

Telegram-оператор данных умеет узнавать таблицы, доступные колонки, связи и ограничения, читать строки по условиям и менять рабочие данные каталога пакетами. Доступны выбор всех записей, ID, диапазон ID и фильтры по значениям; пагинация просмотра не ограничивает массовую операцию. Длинные значения читаются частями. Ключи, права, очереди, аудит, денежный учёт и доказательства проверки защищены; публикация и подтверждённые фото используют обычные специализированные процессы.

Пакет с удалением сначала показывает точную выборку, количество, область действия и сопутствующие новые значения. Кнопка действует 10 минут для того же оператора/чата. Изменившиеся данные требуют нового запроса; записи, добавленные после предпросмотра, не удаляются. `/new` и `/reset` отменяют ожидающие подтверждения. Файлы удаляются после успешного сохранения БД. Активный поиск черновика нужно сначала отменить.

## Админ-панель

Filament доступен на `http://127.0.0.1:8000/admin`. В панели можно:

- искать, фильтровать, создавать и редактировать товары и варианты;
- управлять характеристиками, источниками и локальными изображениями;
- активировать и скрывать товары;
- проверять AI-черновики, AI-запуски, операции и Telegram-журнал;
- хранить ngrok URL и вручную нажать `Set webhook`.

Все таблицы админки по умолчанию открываются с нативным вариантом **«Все»**, включая связанные записи и последние карточки на главной. Можно вручную выбрать 25/50/100; при новом открытии снова показываются все строки. Сохранённые фильтры и настройки колонок остаются на месте.

В **Система → Очистка данных** доступны отдельные кнопки очистки каталога, черновиков и общей очистки для тестов. Общая очистка удаляет каталог, черновики и временные диалоги; справочники и обучение источников удаляются только по отдельным галочкам. В шапках таблиц товаров, черновиков, характеристик и групп есть соответствующие быстрые кнопки. Очистка относится ко всему разделу, независимо от фильтров и страницы.

Перед удалением показываются точные количества, связанные изменения и сохраняемые данные. Открытие окна и отмена ничего не меняют. Подтверждение действует 15 минут; новые или изменённые данные требуют нового предпросмотра. Активные задания блокируют очистку. Настройки, ключи, пользователи, аудит Telegram/AI, подсказки и блокировки источников сохраняются, ID не сбрасываются. Файлы удаляются фоновым обработчиком после успешного сохранения БД и проверки оставшихся ссылок. Автоматическая резервная копия этой кнопкой не создаётся.

«Срабатывания рецепта» считает технически подтверждённые извлечения галереи через Playwright. Это не число готовых товаров и не число ответов Telegram. В черновиках и последних карточках отдельный «Итог карточки» показывает готовность по сохранённым данным, сверке и проверке фото; он также не подменяет подтверждение доставки. Запросы, остановившиеся до создания черновика, доступны в журнале Telegram.

После завершения поиска согласованная карточка без фотографий приходит текстом с возможностью продолжить поиск, без кнопки публикации. Ошибка отправки готового ответа в Telegram повторяет доставку сохранённого результата, не запускает заново оплаченный поиск. Непроверенные фотографии и несогласованные характеристики не становятся готовым товаром из-за остановки поиска.

EAN/UPC, P/N, SKU и полная модель служат альтернативными ключами поиска: все коды не обязаны присутствовать на одной странице. Прочитанные сведения с заводской этикетки сохраняются отдельно от требований оператора. Пригодность фотографий проверяется отдельно от комплектации: одинаковый корпус другой комплектации допустим с указанием существенных отличий, а невидимое различие RAM/SSD не обнуляет фотографии. Даже точная карточка проходит проверку текущих кадров; ошибка или неполнота характеристик возвращает к проверке текста, сохраняя пригодную галерею. Наблюдаемые зеркала источника остаются резервом после независимых карточек.

Публичный каталог использует ровную адаптивную панель из трёх блоков. На странице товара при двух и более фотографиях автоматически включается Swiper со стрелками, пагинацией, клавиатурой и миниатюрами.

Доступ разрешён только пользователю с `is_admin=true` и именем из `ADMIN_NAME`.

### AI-помощник в форме товара

На страницах создания и редактирования кнопка **AI-помощник** открывает выезжающий чат справа. Панель можно закрыть и открыть снова, продолжая редактировать форму. Он использует модель, выбранную в **Настройки → AI**; текущая модель указана в панели.

- **Перевести** заполняет чешские поля названия, описания и характеристик по текущему содержимому формы. Исходный текст, в том числе введённый по-русски, сохраняется.
- **Дополнить товар** ищет сведения в интернете по названию или SKU и дополняет пустые поля с указанием источников. Для общего названия без точной комплектации помощник должен уточнить недостающие данные.
- В чате можно уточнять характеристики и исправлять текст. Если конфигураций несколько, выберите нужную в панели помощника.

Результат применяется к несохранённой форме. Ручные правки, сделанные во время ожидания, сохраняются; пропущенные изменения перечисляются в ответе. Новые бренды, категории, характеристики и группы сначала показываются как предложения и создаются вместе с товаром после обычной кнопки **Сохранить / Создать**. Помощник не публикует товар самостоятельно.

Запрос выполняет очередь `assistant`, которую обслуживает стандартный launcher; в режиме `start-without-telegram.bat` используется изолированная очередь `admin-ai`. Во время ожидания форму можно редактировать, запрос можно остановить. История запроса и расход записываются в **AI-запуски**; чат относится к текущему сеансу формы. Автоматический поиск фотографий этой панелью не запускается.

## Полезные команды

```powershell
php artisan telegram:set-webhook
php artisan telegram:sync-ngrok
php artisan telegram:sync-ngrok --watch
php artisan queue:failed
php artisan queue:retry <uuid>
php artisan queue:restart
php artisan test --compact
vendor\bin\pint --test
```

Для разработки с Vite, логами и всеми worker-ами:

```powershell
composer dev
```

## Linux

Шаблон `deploy/systemd/ningredy-worker@.service` запускает отдельные worker-ы:

```bash
sudo systemctl enable --now ningredy-worker@assistant.service
sudo systemctl enable --now ningredy-worker@voice.service
sudo systemctl enable --now ningredy-worker@media.service
sudo systemctl enable --now ningredy-worker@default.service
```

Для production предпочтительны PostgreSQL/MySQL и Redis. Текущий SQLite настроен на WAL и подходит для одного небольшого локального сервера.

## Границы AI

AI не получает shell или прямой SQL-доступ. Инструменты Laravel валидируют параметры, сервер выполняет операции, а `ai_operations` хранит аудит. Интернет-страницы считаются недоверенными данными. Удаление требует отдельного Telegram-подтверждения.

## Памятка оператора

Короткая памятка для того, кто ведёт бота на своём компьютере — запуск и обновление, команды, что значат сообщения, что делать при ошибке: [docs/operator-memo.md](docs/operator-memo.md).

## Отчёт для разработчика

Команда `/report` в Telegram (или кнопка «Скачать отчёт» на странице «Состояние» в админке, или `php artisan bot:report`) собирает один архив: сводку поисков за 7 дней с итогом каждого (фото, минуты, где остановился, сверена ли карточка), пошаговый журнал каждого запроса, вызовы AI с их стоимостью, карточки, выученные ботом правила сайтов и рецепты галерей, хвост лога ошибок и список настроек без значений. Ключи и пароли в архив не попадают. `/report full` (или кнопка «Отчёт с базой» в админке, или `bot:report --with-db`) добавляет в архив копию базы данных с вычищенными ключами и паролями — по ней разработчик может прогнать свои инструменты как на живой. Если копия не влезает в лимит Telegram (50 МБ), бот пришлёт отчёт без неё и попросит скачать полный в админке. Этот файл — всё, что нужно разработчику, чтобы увидеть, что бот делал на вашей машине; после исправления обновление приходит через `update-and-start.bat`.
